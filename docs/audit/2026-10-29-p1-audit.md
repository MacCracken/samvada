# samvada P(-1) pass — 2026-10-29

**Scope**: a deep P(-1) sweep (CLAUDE.md § Process) of the 1.1.1 tree:
correctness, hardening, security and the CI gates. Source: `src/` (every
native module and the public layer), `deps/samvada_main.c`,
`.github/workflows/`, `tools/`, `tests/`.

**Target release**: 1.1.2, on cyrius 6.7.18.

**File name**: the 1.1.1 close-out is `2026-10-29-audit.md`, from the same
day, so this pass carries the `-p1` suffix.

---

## How this pass was conducted, and its limits

Four independent reviews of the 1.1.1 tree, each blind to the others: the
wire path (framing, descriptors, the receive), the session layer, the
CI gates and supply chain, and a CVE review of libsystemd, logind,
dbus-broker and dbus-daemon from 2022 to October 2026. Findings were
deduplicated, and every repair below was then:

- **pinned** by a test or a CI gate built from the finding's own proof
  of concept;
- **mutation-tested**: the repair reverted, the pin seen to fail — or,
  for blocking I/O, to hang into the timeout, which counts;
- **re-verified adversarially**: five fresh reviewers, one lens each,
  tried to break the repaired tree, and two skeptics tried to refute
  every finding they reported (§ Re-verification).

Ground truth for kernel behaviour was the kernel's
(`net/unix/af_unix.c`, `unix_stream_read_generic`), and for protocol
behaviour sd-bus's and logind's (systemd v262).

Not covered, and why:

- **A seated session.** `TakeDevice` on a real seat would take control of
  the only session available, the maintainer's graphical one. Every proof
  runs over a socketpair; the only live run is the unseated
  init → pump → release → re-init cycle, which takes no control
  (ADR-0004) and returned 0 at every step against dbus-broker 37.
- **The EINTR retries** (M4) have no test. The stdlib cannot install a
  signal handler, and a SIGSTOP/SIGCONT test needs a second process,
  which samvada's tests do not spawn. They are handled, and not claimed
  tested.
- **The release workflow's action steps**, which cannot run off GitHub.

## P1-1 [HIGH] — any local user could plant the descriptor TakeDevice returned

samvada attributed received descriptors to messages through ONE FIFO queue
and, since 1.0.1, closed each consumed message's descriptors by counting
them from its own `UNIX_FDS` header field. A message whose field array
samvada could not walk counted as carrying **none**:

- any **big-endian** message — the framer accepts `B`, but every header
  read in the unmarshaller is little-endian, so the byte-swapped
  `fields_len` overran the message and the walk returned malformed;
- a little-endian message with an **unknown header field of a type the
  walk had no case for** (code 200, signature `y`) ahead of `UNIX_FDS` —
  legal; the spec says unknown fields are ignored.

The one frame an unprivileged peer can push to samvada is a directed
SIGNAL (the 1.0.0 forgery audit). The stock policy lets any user send
signals, dbus-broker delivers a directed signal regardless of match rules,
forwards both shapes unchanged, and enforces `UNIX_FDS` in the sender's own
byte order — so the descriptors arrive with it. samvada's unique name is
one `ListNames` away. So: one such signal carrying descriptor X, and the
next `take_device` returned **X, with success**, instead of logind's Y;
Y then went to the *next* take, for a different device; and with eight
planted, the queue was full and every genuine descriptor after them was
closed on arrival. A compositor drawing to, or reading input from, a
descriptor another local user chose. This is CVE-2022-42012's bug class
(libdbus mishandling descriptors in foreign-endian messages), reached
through samvada's own code; the C shim was never affected — sd-bus reads
no further than the current message.

**Fix**: attribution no longer consults the message at all. Every read is
bounded to the message at the head of the buffer (`dbus_frame_want`,
`dbus_frame_prepare`, `_dbs_recv`) — the rest of its 16-byte header, then
the rest of the message — so whatever descriptors a read delivers arrived
with that message's bytes. This is sd-bus's own rule
(`bus_socket_read_message` reads no further than the current message), and
the kernel's stream semantics make it exact: a unix stream receive detaches
an skb's descriptors when it reads the skb's first byte, and stops after an
skb that carried any. The fd queue therefore holds the head message's
descriptors only, and `dbus_frame_advance` closes every one the caller did
not claim. `take_device` claims by the body's `h` **index**
(`dbus_frame_claim_fd`) — the index was read and ignored before — after
checking the reply is `(hb)`, that `UNIX_FDS` equals what arrived, that the
set was not truncated, and that `inactive` parsed; anything else is
`-EBADF`, the documented peer-bus contract violation, and nothing is handed
out. The 1.0.1 parse-based dropping (`_dbs_unix_fds`, `_dbs_drop_n`,
`dbus_session_drop_fds_of`) is deleted.

**Pins** (`tests/dbus_session.tcyr`):
`test_unparseable_message_cannot_plant_a_descriptor` — the reviewers' three
proofs of concept: a big-endian signal + X, an unknown-field signal + X,
and eight big-endian signals; each time `take_device` returns Y's inode
and every planted descriptor is closed.
`test_take_device_holds_the_reply_to_its_contract` — a descriptor-less
signal immediately ahead of the reply (the bounded-read pin), the index
honoured over two descriptors, count mismatch, index out of range, no
descriptor, wrong signature, missing `b`, and a truncated set whose
`UNIX_FDS` lies to match it. **Mutants**: advance not closing, an
unbounded read, claiming the head instead of the index, and each of the
four reply checks removed — every one fails the suite.

## P1-2 [MEDIUM] — a signal with three descriptors closed samvada's bus

The receive reserved control-buffer room for one descriptor (24 bytes,
which also fits two). A message with three or more truncated
(`MSG_CTRUNC`); the truncation branch discarded the message's bytes and
returned `-EPROTO`, and the session layer — correctly, by sd-bus's
`ERRNO_IS_NEG_DISCONNECT` — read `-EPROTO` as a disconnect and latched the
bus closed. Any bus peer could do it, repeatedly; each reconnect cost the
consumer its session control and its devices. ALANE-1 (1.1.1) had fixed
only this branch's heap growth.

**Fix**: `dbus_sys_recv` reserves `CMSG_SPACE(253)` — `SCM_MAX_FD`, the
most one sendmsg can carry and so the most one stream receive can deliver
— and returns every descriptor in an rx array; it walks every cmsg, not
just the first. `MSG_CTRUNC`, now reachable only when another cmsg shares
the buffer (`SO_PASSCRED` puts credentials first), keeps the bytes and
flags the set incomplete (`dbus_sys_rx_truncated`), which marks the head
message's descriptors unusable instead of closing the bus.
**Pins**: `test_three_fds_do_not_truncate`, `test_ctrunc_keeps_the_bytes`
(`SO_PASSCRED` + 250 descriptors), `test_sustained_ctrunc_is_bounded` (no
heap, no descriptor across 100 truncations) in `tests/dbus_sys.tcyr`;
`test_bus_peer_traffic_cannot_fail_a_call` (the call succeeds past a
three-fd signal and the bus stays open).

## P1-3 [MEDIUM] — 64 one-descriptor signals failed any call

The call loop gave up after 64 reads, a budget that predates the
wall-clock deadline. A descriptor ends a stream read, so 64 one-fd signals
ahead of a reply — or 512 KiB of junk — failed the call with `-ETIMEDOUT`
at once. **Fix**: the deadline is the only bound; every wait is a poll
(`fd_wait_ready`) for the time that is left, so a call also ends AT its
deadline rather than up to one `SO_RCVTIMEO` past it, as it could before
(≈50 s). A read backstop applies only if the clock fails. **Pin**: 100
one-fd signals ahead of the reply, the take succeeds.

## P1-4 [MEDIUM] — an over-cap drain across a send made the reply "stale"

The send-time watermark (1.0.0) was a count of bytes pending at send,
decremented by each consumed message — but not by the bytes an over-cap
drain discarded. An over-cap message straddling the send left the count
above zero, and the genuine reply was refused as predating its request.
**Fix**: stream positions (`dbus_frame_pos` / `dbus_frame_received`; the
framer tracks the position of its buffer's first byte across compaction).
**Pin**: `test_drain_does_not_strand_the_watermark`; the count-based
mutant fails it.

## P1-5 [MEDIUM] — one signal to the consumer failed its call

`SO_RCVTIMEO` makes the kernel refuse to restart an interrupted receive,
so any signal the consumer handles arrived in the call loop as `-EINTR`
and failed the call; in the handshake it became `-EACCES`. **Fix**: EINTR
is retried on the call path, in the wait, and in the handshake, under the
deadline; the handshake now has the call path's deadline and poll too.
**No test** — see § limits.

## P1-6 [MEDIUM] — the surface and boundary gates missed a same-line `public fn`

Both gates matched declarations with line-anchored regexes, so
`fn a() { … } public fn evil() { … }` on one line passed the public-surface
freeze, and an internal declared mid-line was never tried by the boundary
check. **Fix**: `tools/cyr_scan.py` — comment- and string-aware, matches
declarations anywhere, and counts every `fn` and `public` token against the
declarations it parsed, so an unfamiliar form fails the gate. **Pins**: its
`--self-test`, and a CI step that plants a same-line export into a copy of
the bundle and requires the surface gate to fail.

## P1-7 [LOW] — control was taken before device numbers were checked

Both backends range-check `major`/`minor`, but only after the public layer
had sent `TakeControl` — which on a seated VT mutes the keyboard and blanks
the console — for a request that could never be sent. **Fix**: checked
first, in `src/samvada.cyr`. **Pin**: `test_devnums_checked_before_control`.

## P1-8 [LOW] — a bare device count could revoke a device the consumer held

The public layer counted held devices and dropped control when the count
reached 0. A take that failed on samvada's side after logind granted it,
followed by a release of that device, decremented the count for a device it
never counted; at 0 samvada released control, and logind revoked every
device, including the one the consumer was drawing to. **Fix**: devices are
held by number (`(major << 32) | minor`, 256 entries); a re-take of a held
device is refused `-EINVAL` without a round trip (logind would answer
`DeviceIsTaken`); a failed take with nothing held hands control back,
which releases everything logind may have granted; a failed take with other
devices held releases just that device, best effort, unless the bus
failed — for both backends, including the C shim's `F_DUPFD_CLOEXEC`
failure (an interim fix that had the shim release it too was removed:
it sent `ReleaseDevice` twice). **Pins**:
`test_release_of_an_untracked_device_keeps_control`,
`test_failed_take_releases_what_logind_may_have_granted`,
`test_held_device_is_not_taken_twice`.

## P1-9 [LOW] — a failed ReleaseControl was forgotten

The control flag was cleared whatever `ReleaseControl` answered, so one
that timed out left the console muted for the life of the connection.
**Fix**: kept unless the bus has gone (logind drops a departed
controller), so the next last-device release, or `samvada_release`, asks
again; and `TakeControl` is re-sent whenever nothing is held, which logind
answers idempotently for the same controller (`session_set_controller`).
**Pin**: `test_failed_release_control_is_retried`.

## P1-10 [LOW] — a descriptor-less message beside a reply cost it its descriptor

A two-descriptor reply with one queued dropped the next message's, and an
unbounded read taking a signal and the reply together attributed the
reply's descriptor to the signal. Both are P1-1's root, closed by its fix;
pinned by its bounded-read case.

## P1-11 [LOW] — a corrupt stream was still written to

A bad endian byte, a bad version or a header declaring ≥ 128 MiB is never
consumed, so every later read stops at it — but each later call still SENT
its request (a `TakeControl` logind would act on) before reporting the
fault. **Fix**: `dbus_session_call` refuses to send on an unframeable
stream; the errno is unchanged and it is not a disconnect, as in sd-bus.
**Pin**: `test_corrupt_stream_is_not_written_to`.

## P1-12 [LOW] — the receive, the pump and the shim

- **Re-init leaked queued descriptors**: `dbus_frame_init` zeroed the count
  without closing them. It closes them now. Pin:
  `test_frame_init_closes_what_is_queued`.
- **The pump swallowed receive errors** other than a disconnect, so a pump
  on a descriptor gone bad reported a quiet bus forever. They are returned.
  It also read once per call, which with bounded reads would report at most
  one event per pump; it now reads until the socket is empty, capped at 256
  events and 1024 reads like the shim's drain. Pin:
  `test_pump_reports_a_bad_descriptor`.
- **A bus socket on fd 0** (a process that closed stdin) read as "no bus"
  in the public layer and was refused, leaking it; on 1 or 2 a later print
  would write into the dbus stream. It is moved above 2,
  `F_DUPFD_CLOEXEC`. Pin: `test_socket_is_moved_above_stdio`.
- **The shim shared the thread's default bus** (`sd_bus_default_system`),
  so other code in the consumer using the default bus shared samvada's
  session control, and `sd_bus_unref` did not close it. It opens a private
  connection (`sd_bus_open_system`) and closes it with
  `sd_bus_flush_close_unref`.

## P1-13 [LOW] — the parsers' edges

- The header-field walk knew only `s`/`o`/`u`/`g`, so a legal unknown
  field of another type stopped it (P1-1's second shape). Every basic type
  is stepped over now; a container-typed field is refused, fail-closed.
- A defined field with the wrong type was read as if it had the right one
  — a `REPLY_SERIAL` typed `s` as its string's length. It is malformed now,
  as in sd-bus (`bus_message_parse_fields`).
- The walk read `fields_len` before checking the message limit; the limit
  is checked first.
- `AGREE_UNIX_FD` counted as success without a prior `OK`. It answers
  `NEGOTIATE_UNIX_FD`, legal only after authentication; alone it is an
  error now.
- A signature over 255 bytes was written with its one-byte length
  truncated; it poisons the message now.
- `take_device` stored the decoder's `-1201` into `active_out` for a
  malformed `inactive`; it stores 0 and refuses the reply.

Pins: `test_field_walk_steps_over_every_basic_type`,
`test_marshal_refuses_a_long_signature`, SASL case (9).

## P1-14 [LOW] — the spawn scan, the fixture gate and the errno gate

- **The spawn scan** could be walked past, each demonstrated: `SYS_execve`
  and `__NR_execve` (it matched `SYS_EXECVE` only), `execvpe(`,
  `posix_spawnp(`, `clone(`, hex syscall numbers (`syscall(0x3b`),
  `&sys_execve` (a fn pointer, never followed by `(`), any code on a line
  starting with `#` or `*` (dropped as a comment — so a C `#define` was
  never scanned), and hex buffer sizes. It is `tools/security_scan.py` now,
  reading code through `cyr_scan`, with every bypass a positive control in
  its `--self-test`.
- **The corpus gate** decoded the fixtures but never checked they were the
  capture: a fixture edited to agree with a bug decodes fine. CI now checks
  each one's size and sha256 against `MANIFEST.md`, and that every fixture
  is listed.
- **The errno gate** extracted the asserted rows with a regex that also
  matched commented-out asserts. It strips comments first.

## P1-15 [LOW] — no gate checked what the shim stores in each slot

CI cross-checked the C `SLOT_*` offsets against the Cyrius ones, but
nothing checked which wrapper sits at each: two swapped lines in
`samvada_shim_init()` passed every gate. `tools/shim_slot_check.c`
includes the shim, stands in for libsystemd at link time (no `-lsystemd`,
so a new `sd_bus_*` call fails to link), and calls each slot to see what it
sends. Its `-DSHIM_CHECK_SELFTEST` build swaps two slots and must fail; CI
runs both.

## P1-16 [LOW] — tests that could not fail

- The 60 Hz heap test asserted "80 messages were examined" from a counter
  the test incremented itself. It now asserts the framer's consume cursor
  moved past every byte.
- The LOW-5 release test claimed to check that the scratch was wiped and
  asserted only that the API was disarmed. It checks the scratch.
- A `dbus_sys` surplus-descriptor probe assumed the surplus sat at
  `rfd + 1`; it went with the receive's rewrite.
- `test_declared_128mib_fails_both_paths` wrote 8 bytes at offset 12 of a
  16-byte buffer; `store32` now.

## P1-17 [INFO] — tooling

- `tools/dbus_tap.py`'s listening socket had the process umask. Its
  upstream connection authenticates as the tap's user, so anyone who could
  connect got a bus connection with that identity. It is 0600 under umask
  077 now, captures included, and it closes the descriptors it forwards
  (it leaked one per fd-bearing message).
- `tools/differential/` compared a successful take's raw descriptor
  numbers, which differ between backends, and never closed them; and
  `run.sh` takes session control, which blanks a seated console, on
  invocation. It normalises a success to 0 and closes it, and needs
  `SAMVADA_DIFF_TAKES_CONTROL=1`.

## CVE review

No 2022–2026 CVE in libsystemd affects the versions the shim links (259 in
CI, 262 on the development host), and no logind CVE touches `TakeControl`,
`TakeDevice` or device revocation. CVE-2022-42012 (libdbus, foreign-endian
descriptor handling) is P1-1's bug class, reached through samvada's own
code. Consumer floors worth stating, none a samvada defect: **dbus-broker
≥ 32** (≥ 36 preferred) and **dbus-daemon ≥ 1.14.8 / 1.15.6, or any
1.16.x** (CVE-2023-34969, a bus-availability crash).

## Re-verification

Five fresh reviewers, each with one lens — descriptor attribution,
liveness, the public layer and shim, the parsers, the gates — tried to
break the repaired tree, each in its own scratch copy, none touching the
system bus. Two skeptics then tried to refute every finding they
reported, and a completeness critic checked the result against this
report's list, hunted documentation the repairs made false, and ran the
suites on aarch64 under `qemu-aarch64`.

**What held.** Every H1 variant replayed — big-endian, unknown-field,
eight and twenty planted, a 253-descriptor signal, forced truncation,
compaction that moves the reply itself, a late reply after a timeout —
returned the reply's own descriptor, with nothing leaked. M2 held against
2000 three-descriptor signals and against a dribbling peer; M3's
watermark held across compaction and two over-cap drains straddling the
send; EINTR held under 60 SIGSTOP/SIGCONT cycles. No reviewer found a way
to make `take_device` return a descriptor from another message.

**What did not.** 36 findings; 34 confirmed, two refuted. All 34 are
fixed or documented, and each fix is pinned and was mutation-tested (23
further mutants, every one caught). By severity after verification:

| ID | Severity | Finding | Disposition |
|---|---|---|---|
| R-1 | MEDIUM | A device logind already dropped (hot-unplug) stayed in the held table for ever: control never went back, the replugged device could not be re-taken | Fixed: a release forgets the device whatever logind answers |
| R-2 | MEDIUM | `#must_use public fn …` — code after an attribute directive — was invisible to every gate | Fixed in `tools/cyr_scan.py` |
| R-3 | MEDIUM | `pub`, the lexer's synonym for `public`, was not counted: `pub var` exported state past both gates | Fixed in `tools/cyr_scan.py` |
| R-4 | LOW | A received device descriptor could land on 0..2 (the bus socket had been moved; its descriptors had not) | Fixed, both backends |
| R-5 | LOW | A socket that polls readable with nothing to read (one `MSG_OOB` byte) blocked the call past its deadline — for ever without `SO_RCVTIMEO` | Fixed: non-blocking receive after a ready poll |
| R-6 | LOW | A timed-out take cost two budgets; a timed-out `TakeControl` was forgotten | Fixed: control is "may be held" after a timeout; with other devices held nothing more is sent (the first take still hands control back — § Final pass) |
| R-7 | LOW | The SASL handshake kept a 32-read cap that EINTR used up, and its loop reported most failures `-13` (an expired receive was already `-110`) | Fixed: deadline-only, and its own errno per failure; now testable over a socketpair |
| R-8 | LOW | The errno gate counted an assert inside a dead `#ifdef`: a wrong mapping shipped green | Fixed: the fixture file is asserted at run time |
| R-9 | LOW | The spawn scan's syscall-number, C and path spellings; symlinks; `shim_slot_check` ignored arguments | Fixed in the gates |
| R-10 | LOW | The native `-9` diverges from libsystemd per case; the doc's claim about sd-bus was wrong | Documented, measured per case |
| R-11 | INFO | Acceptance of a malformed field array depended on field order | Fixed: every message is validated whole first |
| R-12 | INFO | Hello's and GetSessionByPID's replies, and session paths, were not checked; `OK` without a GUID passed | Fixed |
| R-13 | INFO | A clock failing mid-call turned the wait into a ~24-day poll | Fixed: the call times out |
| R-14 | INFO | A pidfd (`SO_PASSPIDFD`) leaked; a failed connect left queued descriptors; `release_device` did not range-check; a negative fd surfaced as an errno; arity was a comma count; `dbus_tap.py` forwarded 16 descriptors at most | Fixed |
| R-15 | INFO | A big-endian reply times out; an `h` index ≥ 8 is refused; attribution assumes a message's descriptors ride its first byte (as sd-bus does) | Documented |
| — | — | A timed-out take with others held leaves the device stuck; comments overstate sd-bus parity | Refuted |

**The critic's additions.** The send was outside every bound — a broker
that stops reading blocked a call for ever once the send buffer filled —
and is now bounded by the call's deadline, with `SO_SNDTIMEO` as the
backstop (R-16, LOW, fixed). Thirteen documentation claims the repairs
made false are corrected. Its structural point is recorded in
`SECURITY.md`: samvada's device table is a copy of logind's state that
nothing re-syncs, since pause and resume are not delivered (ADR-0004).

**An addition from the CVE review**: `take_device` now checks, by
`statx` and `F_GETFL`, that the descriptor is a character device whose
rdev is the `(major, minor)` asked for, open read-write and not
`O_PATH`, as logind opens it. It asks nothing of the message, so a wrong
attribution can no longer hand out a different device, a socket or a
descriptor nobody could read. It proves identity, not provenance: a
P1-1-style plant of a descriptor naming the same node, opened read-write
by a user allowed to, would still pass it — the attribution fix is what
stops that. (The first cut checked type and rdev only, and accepted an
`O_PATH` descriptor any user can open; § Final pass.)

**aarch64**, under `qemu-aarch64` user mode: every suite passes but for
five asserts in `dbus_sys` and `dbus_session`, all on one cause —
`MSG_CTRUNC` never reaches the guest. The bytes and the descriptors that
fit do arrive. The truncated-set refusal is therefore unproven on
aarch64 until real hardware (roadmap); `-strace` shows only the expected
calls (`recvmsg`, `ppoll` for the poll, `sendmsg`, `sendto`,
`clock_gettime`, `fcntl`, `dup3`).

## Final pass

After the second round of fixes was merged, three more reviewers — the
code, the gates, the documentation — went over the whole tree, and a
skeptic tried to refute each finding. All 30 were confirmed; none
reopened P1-1. Each fix below is pinned, and the code fixes were
mutation-tested (one guard proved redundant and was removed, its case
still refused by the guard that subsumes it).

**Code**

- **F-1 [MEDIUM] The consumer floor moved silently.** The bundle now
  calls `fd_wait_ready` (cyrius 6.6.13) and `sys_statx` (6.6.12), so a
  consumer pinned to 6.6.5–6.6.12 could not build 1.1.2 while every doc
  said 6.6.5. Now a `### Breaking` item, proven by compiling a consumer of
  the bundle on 6.6.12 (refused), 6.6.13, 6.7.5 and 6.7.18 (built).
- **F-2 [LOW] The rdev check accepted an `O_PATH` descriptor**, which any
  user can open on any node, readable or not. It now also requires the
  descriptor to be open read-write, as logind opens devices; the claims
  about what the check proves were corrected (identity, not provenance).
- **F-3 [LOW] A timed-out first take left the console muted** — ADR-0004's
  original defect, reintroduced by R-6's one-budget rule. A first take
  hands control back on any failure again; only with other devices held
  is nothing more sent to a logind that is not answering.
