# samvada A-lane close-out — 2026-10-29

**Scope**: the four A-lane items the 1.0.1 pass left open
(`docs/development/roadmap.md` §The A lane): A-1 resource exhaustion,
A-2 build and supply chain, A-4 the protocol state machine, A-6 the
public API contract. Source: `src/` (all native modules, the public
layer), `dist/samvada.cyr`, `.github/workflows/`, `tools/`.

**Target release**: 1.1.1, on cyrius 6.7.18.

---

## How this pass was conducted, and its limits

The lane's standing rule applied throughout: **every item closes with
evidence, never with "the code was reviewed"**. Every finding below
was demonstrated before it was fixed, every fix is pinned by a test or
a CI gate, and every pin was mutation-tested — the fix reverted, the
pin seen to fail (or, for blocking I/O, hang into the timeout, which
counts). Ground truth for protocol behaviour was taken from source,
not memory: systemd v262 (`sd-bus.c`, `bus-socket.c`, `bus-error.c`,
`bus-common-errors.c`, `errno-util.h`, `logind-session.c`,
`logind-session-dbus.c`) and libsystemd 262 itself, probed.

Not covered, and why:

- A **seated** session. `TakeDevice` on a real seat would take control
  of the only session available, the maintainer's graphical one. The
  native handshake and an init/release cycle were run live, unseated.
- **aarch64 hardware.** aarch64 was exercised under `qemu-aarch64`
  only, where two `MSG_CTRUNC` asserts fail identically on every
  toolchain tried (roadmap).
- **The release workflow's action steps**, which cannot run off GitHub.

## ALANE-1 [MEDIUM] — a peer could grow the heap 8 bytes per message

`dbus_sys_recv_fd_flags` did `alloc(8)` on its `MSG_CTRUNC` branch, and
`alloc()` never frees. Truncation is chosen by the **sender**: attach
more descriptors than samvada's one-fd control buffer holds and every
receive truncates. The 1.0.0 forgery audit established that the one
frame a hostile, unprivileged bus peer *can* push to samvada is a
directed SIGNAL — and a signal may carry descriptors. So any peer on
the bus could grow a long-running compositor's heap without bound.
The existing `MSG_CTRUNC` test ran this branch and checked
descriptors, not the heap.

**Fix**: a once-allocated out-parameter (`_dbus_trunc`).
**Pin**: `tests/dbus_sys.tcyr` — 300 forced truncations, heap delta 0,
descriptor count unchanged (the mutant reinstating `alloc(8)` grows it
2400 B).

## ALANE-2 [MEDIUM] — the native error map was not sd-bus's

samvada promises sd-bus errnos at the FFI boundary, and the native map
held eight hand-picked names. Probing libsystemd 262 showed it wrong on
exactly the errors a logind restart or bus disconnect produce:
`ServiceUnknown` -2 (sd-bus -113), `NoReply` / `Disconnected` /
`NameHasNoOwner` / `NoSessionForPID` all -5, logind's `DeviceIsTaken`
-5 instead of -22, and every `System.Error.<ERRNO>` but `EBUSY` -5
(logind replies with that family for any plain errno). Two of the
existing pins asserted the wrong values.

**Fix**: the table is sd-bus's own — `tests/fixtures/sdbus_errno_map.tsv`
(186 rows) is `tools/sdbus_errno_probe.c`'s output from libsystemd.
**Pin**: every row asserted; CI re-runs the probe against the runner's
libsystemd and checks the test's rows are the fixture's. Checked on
libsystemd 262 and 259; `EFTYPE`, the one row they disagree on, is
omitted.

## ALANE-3 [MEDIUM] — a dead connection looked like a quiet one

After the bus closed, `pump_signals` returned 0 events on every call,
so a consumer pumping at 60 Hz could not tell a quiet bus from a gone
one; a call after the drop wrote to the dead socket. The call path's
own codes also diverged from sd-bus: EOF mid-call -107, a cut stream
-71, a failed send -32, where sd-bus answers `-ECONNRESET` for all
three (`bus_enter_closing`, `bus-socket.c:674-677`) and `-ENOTCONN`
for every call after.

**Fix**: a closed-connection latch (`_dbs_closed`) with sd-bus's
`ERRNO_IS_NEG_DISCONNECT` classification. **Pin**: half-closed and
departed peers over a socketpair — the pump reports -104, a later call
is -107 and writes nothing (the peer reads `EAGAIN`).

## ALANE-4 [LOW] — descriptors on replies that should carry none

An ERROR reply, and the reply to every call but `TakeDevice`, was
consumed without dropping its descriptors. One left at the head of the
FIFO queue was returned by the next `take_device` as its own —
demonstrated: with the ERROR-path drop removed, `take_device` returns
inode 7311388, the stray's, not 7311390. Only the broker and logind
can send a reply, and neither puts a descriptor on these, hence LOW;
the consequence, a compositor drawing to the wrong device, is the one
1.0.1 already fixed for signals.

**Fix**: every consumed message drops its own (`dbus_session_done`);
`take_device` takes a descriptor only if its reply declared one.
**Pin**: `test_stray_reply_descriptors_are_closed`, plus the
Pause/Resume ordering tests.

## ALANE-5 [LOW] — every logind call grew the heap

Each call `alloc()`ed a buffer to copy a string literal into, per call:
take_control 200 B, release_control 192, take_device and
release_device 200, GetSessionByPID 336, and a full init/release cycle
600 B, measured live on the system bus. Consumer-driven and slow, but
unbounded in a process that lives for days.

**Fix**: literals passed straight to the marshaller; the connect
path's buffers allocated once. Wire bytes byte-identical before and
after, for all five logind calls. **Pin**:
`test_logind_calls_do_not_grow_the_heap`; the live cycle measured 0 B.

## ALANE-6 [LOW] — a forged header could start an ~8 GiB drain

The framer drained an over-cap message of any declared length. One
16-byte header with body and fields both `0xFFFFFFFF` committed it to
discarding ~8 GiB before framing another message. sd-bus refuses
`>= 2^27` (`BUS_MESSAGE_SIZE_MAX`) with `-ENOBUFS`. A conforming broker
never forwards such a header, hence LOW.

**Fix**: refused on sight, `-ENOBUFS`, on both paths. **Pin**: the
spec boundary in `tests/dbus_frame.tcyr` (`2^27` refused, `2^27 - 8`
drained) and the session-level test.

## ALANE-7 [LOW] — every internal was consumer-reachable

Cyrius has had file-level visibility since 6.5.0, and samvada never
used it, so all 201 of 1.1.0's bundle fns were reachable — including
`dbus_session_set_timeout_ms`, which sets every call's budget.

**Fix**: `src/visibility.cyr` makes the bundle private-by-default; the
eight frozen fns are `public`. Verified for consumers on cyrius 6.6.5,
6.7.5 and 6.7.18. **Pin**: `tools/boundary_check.py` compiles a
consumer calling every one of the 204 internals and requires each to
be refused. **Limit**: an `object;` build still exports private fns as
GLOBAL DEFAULT symbols (6.7.18), so C code linked against it — the
shim path — can still reach them.

## ALANE-8 [LOW] — release assets were not checked against the tag

A consumer fetches the bundle from the git tag; `SHA256SUMS` describes
the release assets; nothing checked they were the same bytes, and the
`.deps` sidecar consumers also fetch was not published at all.

**Fix**: `release.yml` refuses to publish unless the regenerated
`dist/` is the tag's, and publishes `samvada-<tag>.deps`. The
first-resolve check is documented and was verified against the real
1.0.1 release.
