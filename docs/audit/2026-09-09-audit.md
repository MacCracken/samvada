# samvada P(-1) hardening + security audit — 2026-09-09

**Scope**: full P(-1) pass over the v0.5.0 surface — `src/samvada.cyr`,
`src/samvada_ffi.cyr`, `src/main.cyr`, `deps/samvada_main.c`,
`tests/*`, `.github/workflows/*`, and every doc that makes a
security or behavioural claim.

**Auditor**: internal, multi-agent. Eight independent audit
dimensions, each finding adversarially refuted by a separate
verifier before admission; plus a completeness critic; plus
direct orchestrator verification of every finding admitted
below.

**Target release**: 0.5.1.

**Posture**: this supersedes the "pre-audit" gating in
`SECURITY.md` §Audit History. That gating rested on the premise
that the C-shim surface was transitional and therefore not worth
auditing yet. The premise was wrong in a specific and expensive
way: the transitional surface had never been executed against a
real bus, and it contained a defect that made the project's
headline feature unusable in every environment for five
consecutive releases. Deferring the audit is what let that
survive. See CRIT-1.

**Method**:
- Per-file code walk of the whole surface (~230 LoC Cyrius +
  ~330 LoC C).
- Strict-flag rebuild: `-Wall -Wextra -Werror -Wshadow
  -Wconversion -Wsign-conversion -Wcast-qual -Wformat=2
  -Wpedantic` against libsystemd 261 — **clean**, and
  `cc -fanalyzer` — **clean**. (The 2026-05-01 review's
  `-Wconversion` claim has not rotted.)
- **Live-bus probing against a running `systemd-logind`.** This
  is the method change that mattered. Every prior review reasoned
  about the protocol from the repo's own documentation; this one
  issued the calls.
- Mutation testing: each repair reverted in turn to prove its
  test actually fails.
- Banned-pattern sweep, re-run after proving the existing sweep
  could not fire.

Two CRITICAL findings dominate this pass, and they share a root
cause: **no code path in this repository had ever been executed
against a real dbus daemon or a real consumer link.** Everything
was pinned structurally — slot offsets, null-safety, idempotency
— against a mock table that could not fail in the ways that
mattered. The structural pins were all green while the product
did not work.

The 2026-05-01 review is not at fault for missing these; it
scoped itself to a code walk and said so. What is at fault is the
gate design: M1 has read *"code-complete, awaiting consumer
e2e"* since 0.2.0, and the e2e that would have caught both
CRITICALs was the one thing permanently deferred.

## CRIT-1 — `samvada_session_take_device()` could never succeed: `TakeControl` is never sent

**File**: `deps/samvada_main.c` (no `TakeControl` wrapper existed),
`src/samvada_ffi.cyr` (no slot), `src/samvada.cyr:samvada_init`.

**Defect**: logind requires `TakeControl(b force)` on the session
before it will honour `TakeDevice`, and the control grant is bound
to the **bus connection** that made it. samvada 0.2.0 through
0.5.0 never sent it. There was no FFI slot for it, no C wrapper,
and no Cyrius call site.

**Failure scenario**: every call. `samvada_session_take_device(226, N)`
returns logind's `org.freedesktop.login1.NotInControl`. There is
no input, no environment and no consumer for which the shipped
code path succeeds.

**Reproduction** (single sd-bus connection, samvada's exact
sequence vs. the corrected one):

```
A) GetSessionByPID -> TakeDevice                (0.2.0-0.5.0 behaviour)
   TakeDevice(226,1) -> FAIL: "You are not in control of this session"
                              [org.freedesktop.login1.NotInControl]

B) GetSessionByPID -> TakeControl -> TakeDevice  (0.5.1 behaviour)
   TakeControl -> OK
   TakeDevice(226,1) -> FAIL: "Operation not permitted"
                              [org.freedesktop.DBus.Error.AccessDenied]
```

The **error changing** between A and B is the proof: `TakeControl`
advanced the call past logind's control check. B's `AccessDenied`
is an environment fact, not a protocol one — the probing session
was `Type=tty Class=user Seat="" Remote=true`, and a seatless
session can never own a DRM device. So:

- `TakeControl` is **necessary**, and its absence is a guaranteed
  failure. Proven.
- Whether it is **sufficient** requires an active seated session.
  Still hardware-gated, unchanged, and explicitly **not** claimed
  by this audit.

Confirmed present on the live interface and previously unwired:

```
busctl introspect org.freedesktop.login1 <session> org.freedesktop.login1.Session
  .TakeControl         method  b   -   -
  .ReleaseControl      method  -   -   -
  .PauseDeviceComplete method  uu  -   -
```

**Why five releases missed it**: every test is a structural pin
over a NULL-kind mock table. No test, and no CI job, has ever
issued a logind call. `docs/architecture/dbus-marshalling.md` —
the document the future native marshaller will be built from —
documented three method calls and two signals and omitted the
session-control handshake entirely, so the gap was faithfully
mirrored in the specification as well as the code.

**Fix (0.5.1)**: two slots appended after `kind`, exactly as
ADR-0002 requires — `samvada_slot_take_control()` → 72,
`samvada_slot_release_control()` → 80, `samvada_ffi_size()`
72 → 88, `kind` unmoved at +64. C wrappers `sb_take_control` /
`sb_release_control` (2 args each, well inside the ≤6 ceiling).
`samvada_init` issues `TakeControl` immediately after resolving
the session path; `samvada_release` issues `ReleaseControl` before
closing the bus. **No public signature changes.** A table whose
`take_control` slot is null — i.e. a pre-0.5.1 backend — makes
`samvada_init` return `-38` (`-ENOSYS`) rather than proceed into a
guaranteed `NotInControl`.

**Tests**: `test_init_takes_session_control` (dispatch order and
count), `test_init_rejects_table_without_take_control`,
`test_release_drops_control_and_closes`. Mutation-proven:
deleting the `TakeControl` call fails 7 asserts.

**End-to-end verification of the fix.** After the repair, a full
consumer binary — Cyrius object + C shim + consumer-owned
`main()`, linked against libsystemd — was built and run against
the live system bus:

```
samvada_init (incl. TakeControl) -> 0
take_device(226,1)               -> -13
```

`samvada_init` returning **0** means the whole chain succeeded:
bus open → `GetSessionByPID` → `TakeControl`. The `-13`
(`-EACCES`) from `take_device` is the *environment* — the probe
ran from a `Seat=""` session, which can never own a DRM device —
and crucially it is **not** `-22`, which is what
`NotInControl` squashes to and what every pre-0.5.1 build
returned. The fix is verified through the complete stack: Cyrius
→ FFI table → C shim → libsystemd → dbus → logind.

**Not fixed, same root cause**: `PauseDeviceComplete(uu)` is still
unwired. logind expects the client to acknowledge a `PauseDevice`
of type `"pause"`, or it stalls the VT switch until timeout. This
is inseparable from the signal-delivery gap (MED-7) and is routed
to the roadmap rather than half-built here.

## CRIT-2 — the documented consumer integration cannot link: two `main()` definitions

**File**: `deps/samvada_main.c` (entry point),
`docs/guides/consumer-link.md`.

**Defect**: `deps/samvada_main.c` defined `int main(int, char **)`
unconditionally. Every real consumer already defines `main()` —
mabda's `deps/wgpu_main.c:435` does. The documented two-stage
build tells consumers to link both objects.

**Reproduction**:

```
cc samvada_main.o consumer_main.o stubs.o $(pkg-config --libs libsystemd) -o out
/usr/bin/ld: consumer_main.o: in function `main':
multiple definition of `main'; samvada_main.o:samvada_main.c:(.text+0x60d): first defined here
collect2: error: ld returned 1 exit status
```

mabda's own docs (`docs/guides/native-migration.md:133-134`,
`CLAUDE.md:177`) instruct exactly this link. It has never been
able to succeed.

**Reachability**: 100% for any consumer that does anything beyond
init-and-exit. samvada's CI never caught it because the C-shim job
linked against **stub objects that deliberately omit `main()`** —
the one shape no real consumer has.

**Fix (0.5.1, BREAKING at the link surface)**: `long
samvada_shim_init(void)` is now the library entry point; `main()`
is compiled only under `-DSAMVADA_STANDALONE_MAIN`. The Cyrius
public API is untouched — the break is in how the C object is
linked, and pre-1.0 that is the right trade rather than carrying
an unusable shape into 1.0.

**Coupled fix**: the fn-table was a **stack local** in `main()`.
samvada *borrows* that pointer — `_samvada_slot()` re-reads
`load64(_samvada_table + off)` on every dispatch, it never copies
the 72 bytes — so under the library-style entry the frame would
pop while the pointer stayed live. The table is now
`static int64_t samvada_fn_table[FFI_SIZE / 8]` at file scope.

The comment that justified the stack table read: *"Stack-resident
is fine because samvada_main() never returns until the process
exits."* That is false — `samvada_main` calls `samvada_init` and
returns immediately. It was harmless only because the old `main()`
exited on the next line. A second wrong comment in
`src/samvada.cyr` claimed the table *"lives in C static memory"*,
which was aspirational rather than descriptive. Both are corrected,
and the borrow contract is now stated in `public-api.md` instead of
living in a comment that denied it.

**New CI gate**: a link test that reproduces the real consumer
shape — consumer-owned `main()` plus the shim — replacing the
stub-based test that could not fail.

**CRIT-2b — two more reasons the consumer build could not work**,
found while verifying the fix end-to-end. Both are now documented
in `consumer-link.md` with executed commands:

- **`cyrius build … --emit-object` does not exist.** cyrius 6.6.1
  has no such flag (`error: unknown flag '--emit-object'`), and
  `cyrius build` emits a finished executable, not a relocatable.
  A linkable object needs the `object;` directive piped through
  `cycc` — the same pattern mabda uses. So the documented recipe
  could not even produce the object it then told you to link.
- **Symbol localization was never documented and is mandatory.**
  A Cyrius object exports its own `memcpy`, `memset`, `strlen`,
  `strchr`, `strstr`, `memchr` and `atoi` as global `T` symbols.
  Linked against libsystemd without `objcopy -L`, *libsystemd's*
  calls bind to Cyrius's implementations. Measured on an
  otherwise-identical build:

  | | `samvada_shim_init()` |
  |---|---|
  | without `objcopy -L …` | **`-107`** (`-ENOTCONN`) |
  | with `objcopy -L …` | **`0`** |

  The build succeeds either way and nothing in the failure points
  at symbol interposition. mabda carries the `objcopy` step in its
  Makefile for its own shim; samvada's guide never mentioned it.
- **The pinned tag did not exist.** The guide gave
  `tag = "v0.2.0"`, but every tag samvada has ever pushed is
  **unprefixed** (`git tag` → `0.2.0 … 0.5.0`). The `v`-prefixed
  form resolves to nothing. (The *release workflow* accepts both
  styles, which is presumably where the confusion came from — but
  no `v`-prefixed tag was ever actually created.)
- **`lib/samvada/deps/samvada_main.c` does not exist.**
  `cyrius deps` copies only the `modules` list into `lib/`, so
  `lib/samvada.cyr` lands but no `lib/samvada/` directory is ever
  created. The full checkout is cached at
  `~/.cyrius/deps/samvada/<tag>/` (verified: that path exists for
  `0.4.1` on the audit host). Every `cc` command in the old guide
  pointed at a path that is not on any machine.

## MEDIUM findings (all fixed in 0.5.1)

| ID | File | Defect | Fix |
|---|---|---|---|
| MED-2 | `samvada_main.c` | `major`/`minor` silently truncated 64→32 with no range check at any layer, while SECURITY.md claimed they were "validated at C boundary" | `devnum_ok()` bounds check, `-EINVAL` on violation — makes the doc's claim true |
| MED-3 | `samvada_main.c:sb_take_device` | `dup()` **clears** `FD_CLOEXEC`, so the DRM-master fd survived any `execve` and leaked master rights into unrelated children | `fcntl(fd, F_DUPFD_CLOEXEC, 0)` |
| MED-4 | `samvada.cyr:samvada_session_release_device` | Returned **1** on success — `sd_bus_call_method` returns a positive value on success and it was passed straight through, contradicting the documented `0 \| -err` contract in four places | Normalised in both the C wrapper and the Cyrius fn |
| MED-5 | `samvada_main.c:sb_pump_signals` | Unbounded `for(;;)` drain; one call measured captive **0.77 s** under an unprivileged local signal flood | 256-event cap. The frozen zero-arg signature forbids a parameter, so the cap lives in the wrapper; residue drains next tick |
| MED-6 | `samvada.cyr:samvada_init` | Accepted **any** non-zero `kind`, so a wrongly-shaped table whose +64 word happened to be non-zero got dispatched as function pointers | Whitelist `LIBSYSTEMD` / `PURE_CYRIUS`, else `-EINVAL` |
| MED-7 | `samvada_ffi.cyr`, docs | Slots 48/56 populated by the shim but dispatched by **no** Cyrius code, and no public API installs a match rule — so `PauseDevice`/`ResumeDevice` are never delivered, while four documents claim the subscription ships | Documented truthfully in 0.5.1; **wiring routed to the roadmap** |
| MED-8 | `samvada.cyr:samvada_init` | Failure *after* the bus opened returned the error but left `_samvada_table`/`_samvada_bus` set — leaking the `sd_bus` and leaving the public API armed on a half-initialised samvada | `samvada_release()` on every late-failure path |
| MED-9 | both workflows | Unpinned installer piped from a mutable branch into `sh`, in a job that had already run `actions/checkout` with `persist-credentials` — the job's `GITHUB_TOKEN` was on disk, readable, while upstream code executed with `contents: write` | Pinned commit + `sha256sum -c`; `contents: read` by default with write only on the publishing job; `persist-credentials: false` everywhere |
| MED-10 | `ci.yml` | The security deny list **could not fire**: it grepped `sys_system` (does not exist in the stdlib) and numeric literals the codebase never writes, while `sys_execve` / `sys_fork` / `syscall(SYS_EXECVE, …)` all passed. Proof-of-miss: `sys_execve("/usr/bin/id", …)` added to `src/main.cyr` passed **every** gate | Symbol names + `SYS_` constants + widened numeric set, under `grep -E`, across `src/ tests/ deps/` |
| MED-11 | `ci.yml` | The C shim — shipped as a release artifact, compiled into consumer binaries, and the only code touching raw pointers and fds — was scanned by **nothing** | Scan scope widened to `deps/`; C-specific spawn patterns added |

## LOW findings (all fixed in 0.5.1)

Closing two findings **open since 2026-05-01**:

- **LOW-1** (was LOW-1) — `sb_get_session_path` passed `path`
  straight to `strlen` without a NULL check. The original
  deferral said the one-line guard *"ships under a behavior change
  that wants its own test"*; the test never materialised and the
  rationale was self-perpetuating. Now guarded, `-EINVAL`.
- **LOW-5** (was LOW-2) — `samvada_release` left the scratch
  buffers populated. **New angle that changes the assessment**:
  `_samvada_outs` holds a raw `sd_bus *`, which is *dangling*
  after `close_bus` — not merely "an fd index" as originally
  characterised. Both buffers are now zeroed on release.

Also fixed: `-EINVAL` bounds check on `out_buf`/`out_buf_len`
before the `(size_t)` cast that a negative length would defeat
(LOW-4); `sb_unsubscribe` rejects `slot_ <= 0` so a caller who
forgot to check `sb_subscribe_pause_resume`'s negative-errno
return cannot turn an errno into a wild pointer (LOW-7);
mechanical C-vs-Cyrius offset cross-check in CI (LOW-15) —
ADR-0002 and `public-api.md` both **claimed** the test pin froze
this contract, and it never did, it only checked the Cyrius side;
version-triple-vs-`VERSION` gate (LOW-14); `dist/samvada.deps`
freshness (LOW-13); `CYRIUS_DCE=1` on the released binary
(LOW-16), which was declared the CI default in CLAUDE.md but set
by no workflow.

### Test-suite findings

The suite grew **38 → 114** asserts, mostly because a
long-standing claim turned out to be false.

- **The "HW-gated" excuse was wrong.** `take_device` /
  `release_device` / `pump_signals` were documented as untestable
  without hardware. The fn-table is just function pointers: a
  pure-Cyrius mock backend exercises the entire dispatch path —
  argument marshalling, out-parameter reads, error mapping, call
  ordering — with no bus, no logind and no device. That mock now
  exists.
- **Vacuous assertions.** `test_init_rejects_null_table` passed
  with the guard deleted. `"fresh slot is 0"` could not fail —
  the bump allocator hands out untouched pages, so deleting
  `samvada_ffi_alloc`'s zero-fill left it green. Both are now
  mutation-proof.
- **`samvada_ffi_set_slot`'s null guard was untested** while
  `get_slot`'s was pinned — and `set_slot` is the *write*.
- **No dispatch-wiring pin.** A misroute (say `take_device`
  reading slot 24) would return a plausible value — including
  fd 0, i.e. stdin — with the suite green. Now pinned per fn.
- **`samvada_main` had no test at all**, despite its return value
  becoming the process exit code.

Every repair in this release is mutation-proven: reverting the fix
fails the suite.

## Refuted before admission

Recorded because a refuted finding is a result, and because two of
these were plausible enough that a less adversarial pass would
have shipped them as fixes.

1. **"Audit line citations are stale after the 0.5.0 reformat."**
   Refuted, and *inverted*: the citations refer to the pre-fix
   0.2.x tree the review actually examined.
   `git show 0.2.1:src/samvada.cyr` puts `samvada_release` at line
   155 and `samvada_init` at 61 — matching the doc exactly. The
   citations are correct; checking them against `HEAD` was the
   error.
2. **"`-EBUSY` + the documented release rule tears down a live
   session."** Refuted on the premise. Both doc sites scope the
   promise by *state*, not by "any error", and the `-EBUSY` reject
   fires before any module state is touched.
3. **"SECURITY.md's audit gating contradicts `docs/audit/`."**
   Refuted: the 2026-05-01 document explicitly distinguishes a
   *hardening review* from the formal pre-1.0 *audit* in its own
   §Posture. The project's two-tier vocabulary is consistent.
4. **"The dup-safety principle is overbroad."** Refuted: the shim
   receives exactly one `SCM_RIGHTS` fd today and dups it
   correctly. (The bullet is nonetheless *reworded* in 0.5.1,
   because `dup()` → `F_DUPFD_CLOEXEC` changed underneath it.)
5. **"CLAUDE.md's per-release hardening cadence contradicts the
   v1.0 audit gate."** Refuted on the same two-tier reading.
6. **"The `ffi_alloc` bench grows the heap 68 MiB per run."**
   Refuted on mechanism: `_LINUX_CHUNK` is 256 MiB and
   `alloc_init()` pre-maps one, so the bench never triggers a
   second `mmap`.

## What this audit does NOT cover

Unchanged from 2026-05-01 except where noted:

- **Live-bus behavioural validation.** CRIT-1 was found and its
  *necessity* proven live, but no end-to-end `TakeDevice` has ever
  succeeded, because that needs an active **seated** session
  holding a DRM device. The probing host had no seated session.
  This remains the M1 gate and it is now the single most valuable
  unverified thing in the project.
- **`PauseDevice`/`ResumeDevice` delivery**, and
  `PauseDeviceComplete`. Not wired (MED-7). The Cyrius-fnptr-as-
  `sd_bus_message_handler_t` callback ABI was checked and is
  sound, but it is unreachable, so it has never actually run.
- **Thread safety.** Module-scope state, no locking. Consumers
  must serialize. Now documented consumer-facing rather than only
  inside an audit file.
- **The native dbus marshaller.** ~650–1010 LoC of hand-rolled
  byte parsing will replace libsystemd's validated parser. That
  substantially *enlarges* the audit surface and needs its own
  pass before 1.0 — see `docs/development/roadmap.md`.
