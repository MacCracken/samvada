# samvada — the frozen public API surface. One "name/arity" per line,
# plus an ffi-leak rule column.
#
# This file is the mechanical form of two invariants that were
# enforced by review only until 1.0.1 (the first a v1.0 criterion of
# the pre-1.0 roadmap, the second a CLAUDE.md rule):
#
#   * "Public API frozen — every exported symbol documented + tested"
#   * "Do not expose FFI types in public function signatures"
#
# tools/surface_check.py diffs dist/samvada.cyr — the bundle a
# [deps.samvada] consumer actually links — against this list, and CI
# fails on any difference. Adding, removing or re-signing a public fn
# therefore requires editing this file, which is what makes "frozen"
# mean something rather than describing an intention.
#
# Rules:
#   clean           the signature must not name a fn-table parameter
#   leaks-fn-table  it does, deliberately, and public-api.md says why
#
# SCOPE (1.1.1, A-6): these are the bundle's `public fn`s, and they are
# ALL a consumer can reach. dist/samvada.cyr is private-by-default
# (src/visibility.cyr); every other fn in it — 204 at 1.1.1 — is
# refused at compile time as "private to its file", which
# tools/boundary_check.py proves in CI by calling every one of them.
# Until 1.1.1 all of them were reachable and only documented unstable.
#
# samvada_init and samvada_main take a fn-table because they are the
# C-shim entry points and predate the invariant; samvada_native_init
# exists precisely so a native consumer never handles one.
samvada_version/0                clean
samvada_init/1                   leaks-fn-table
samvada_main/1                   leaks-fn-table
samvada_native_init/0            clean
samvada_session_take_device/2    clean
samvada_session_release_device/2 clean
samvada_pump_signals/0           clean
samvada_release/0                clean
